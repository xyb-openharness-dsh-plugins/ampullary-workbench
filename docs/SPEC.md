## 一、问题、用户与最小闭环

### 1.1 这个病的信息断档在哪里

壶腹部腺癌（ampullary adenocarcinoma）长在十二指肠大乳头（Vater 壶腹），是胆管、胰管、十二指肠三者的交汇点。它在患者端造成三个特有的断档，家族里现有工作台都覆盖不到：

1. **"我这是哪个癌"没人讲清**。病理报告常写"壶腹部中分化腺癌，肠型，浸润至十二指肠固有肌层"，而中文科普基本把它并进"胰腺癌"或"胆管癌"讲。患者拿到的 T 分期来自 AJCC 8th 的**壶腹专属表**（按浸润深度分 T1a/T1b/T2/T3/T4），和胰腺癌、胆管癌的表**不是一张**，三者不换算。
2. **术前减黄那 2–4 周最焦虑，却没有记录工具**。黄疸是首发症状，多数人要先做 ERCP 支架或 PTCD 减黄再手术。这段时间每 2–3 天一个胆红素值，散在门诊本、出院小结、微信截图里。患者想知道的是"降了多少、第几天了、下次抽血是什么时候"，而不是"我的病好不好"。
3. **Whipple 术后出院小结里的词没人翻译**。"胰瘘 B 级""胃排空延迟""胆肠吻合口"这些词出现在出院小结上，患者不知道它是什么、下次复查查什么、哪些症状要提前回院。但这些分级由外科按 ISGPS 标准记录，工具不能重算，只能照录 + 解释术语 + 指向医生。

### 1.2 用户

| 角色 | 主要诉求 | 不许越界的地方 |
| --- | --- | --- |
| 术前等待手术的患者（含家属代管） | 减黄进度、术前准备清单、要问医生的问题 | 不判断"能不能手术""减黄够不够" |
| Whipple / PPPD 术后随访者 | 并发症原文归档、复查节奏、营养与胰酶、体重与血糖 | 不判断"恢复得好不好""要不要调药" |
| 复发/转移后寻求试验者 | 档案成型、试验检索、按字段重合度看候选 | 不判断"你符不符合入组" |
| 患者组织志愿者 | 帮病友把资料整理成可核对档案 | 不代替医生、不留存他人数据到云端 |

### 1.3 最小闭环

```
导入资料 → 核对候选 → 入档（事实四层：报告原文 / 医生口述 / 自测 / 家属补充）
        → 各自成线（不合并）→ 复诊准备材料 → 带去门诊
```

失败恢复：导入失败分「可重试」（网络/授权/超时）与「文件本身不行」（扫描件无文字层、加密、超 200 MB），前者留 `pending_parse` 等配好再点，后者明说为什么不行，不静默丢弃。

成功标准（可观察）：用户能在一个页面里点开任意一条记录的来源（哪份报告、哪一页、谁录入、哪一天），并能导出一份门诊可用的清单。

## 二、方案与 ADR

### ADR-1 为什么单独立仓，不并进 BiliPal 或 PDAC

| 候选 | 好处 | 为什么否 |
| --- | --- | --- |
| A. 挂在 BiliPal（胆道癌）下加一个 Tab | 复用胆道梗阻、支架、胆红素已有实现 | T 分期表不同、病理亚型不同、试验入组口径不同；一个台里塞两套分期会诱导换算 |
| B. 挂在 PDAC（胰腺癌）下 | 同术式（Whipple）、同术后并发症 | 壶腹 T 分期按十二指肠壁/胰腺浸润深度定义，胰腺按超越胰腺与血管，混在一起会让用户以为"同一期别含义相同" |
| **C. 单独建仓（选中）** | 三套分期并列不换算、病理亚型与鉴别独立、试验走 basket 宽口径 | 成本是要重写五套测试（LESSONS L29） |

### ADR-2 三条主线并列，不压成一个总分

术前减黄线（胆红素/支架/PTCD）、肿瘤负荷线（CA19-9/影像）、术后功能线（体重/白蛋白/血糖/胰酶）**三条量纲不同、时间窗不同**。压成一个"病情分"就是把第 ③ 层判断伪装成数字。所以：一图秀里三条线**各自按自身量纲归一化**（16 号 R1），每张图必须有可见的"不可比"说明。

### ADR-3 分期照录不换算

AJCC 8th 壶腹 / 胆管 / 胰腺三套 T 分期并列展示，各自标出处与版本；用户输入的是**医生写的原文**，工具不推、不算、不给"相当于"。数据层不设任何 `derived_stage` / `stage_group` 列。

### 目标宿主能力表

| 能力 | 官方合同 | 本机核验 | 替代路径 |

## 四、数据与 API

表清单与冻结哈希见 `docs/SCHEMA.md`、`docs/freeze-contract.md`（G3 产出）。

核心实体：

| 实体 | 说明 | 关键约束 |
| --- | --- | --- |
| `document` | 原件（报告/影像/出院小结） | 路径由用户选定；`file_path` 可为仓库相对路径（演示库） |
| `fact` | 从原件核对来的事实 | 四层来源 `report/dictation/self/family` 不合并；每条可点回 `document` |
| `pathology` | 病理与亚型 | `subtype ∈ {intestinal, pancreatobiliary, mixed, unknown}`；分期原文列只存字符串 |
| `stage_note` | 分期原文 | `system ∈ {ajcc_ampulla, ajcc_bile_duct, ajcc_pancreas}` 三行并列；**禁 derived 列** |
| `drain_event` | 术前引流 | `modality ∈ {ercp_plastic, ercp_metal, ptcd, none}` |
| `metric` | 指标点 | `kind ∈ {num, grade, qual}`；分类值 `dec IS NULL` |
| `complication` | 术后并发症 | 分级只存原文 + 记录人 + 日期，不重算 |
| `trial_snapshot` | 试验本地快照 | 只存公开登记信息 |
| `saved_trial` | 用户收藏的试验 | **只有** `(trial_key, saved_at)`；禁 `match_score/eligible/suitability` |

API（与 `docs/API-CONTRACT.md` 一致）：`apiBase` 不含 `/api`，调用写 `${apiBase}/api/xxx`。能力位含 `mineru-settings` / `parse` / `trial-search`。

## 七、资源与 Agent

接入 DSH 原生 Agent，形态 `customFrame`：`businessSide:'left'`，`businessWidth 0.65 + AGENT_PANE.default 0.35 = 1`。顶栏三段式（品牌 + 版本 chip / 状态说明 / 主按钮组）。

- 五态文案固定：`AI 对话 / 正在连接… / 收起 AI 对话 / 打开 AI 对话 / AI 对话暂不可用`。
- 面板可拖 25%–45%，`role="separator"` + `aria-valuenow` + ←→ 2% + Home/End，读回过 `clampAgentWidth()`。
- **收起 ≠ 结束会话**：不调用 close/delete，原生会话节点恒定挂载。
- 窄容器 <760px 覆盖式抽屉 ≤420px，splitter 不出现。
- 演示态**不伪装已接通**（19 号第 12 条 / 34 号）：写明"未发送任何内容 / 待你发送 / 真实版本走宿主接口"。

细节引用 `prompts/DSH-AGENT-PANE-INTEGRATION.md`、`docs/20-AGENT-PANE-DESIGN.md`。
