### 定义

壶腹部腺癌是发生在十二指肠大乳头（Vater 壶腹）区域的腺癌。这个位置是胆管、胰管与十二指肠三者交汇的地方，所以它既不像胆管癌也不像胰腺癌，医学上单独列一类。这一点在中文资料里最容易被抹掉：大量科普把它并进「胰腺癌」或「胆管癌」里讲，导致患者听到的解释与自己报告上的分期对不上。

「壶腹周围癌」是更大的说法，包含壶腹癌、胰头癌、远端胆管癌与十二指肠癌四种；四者的分期表与手术方式不完全相同。病理上常分肠型、胰胆型与混合型三个亚型，由病理医生按镜下形态与免疫组化判定。

### 目前治疗全景概要

按病程三段列出指南里出现过的手段类别。这是「世界上大致有哪些办法」的地图，不含剂量、疗程与适用条件。

- **术前（以梗阻性黄疸首发时）**：胆道引流减黄（ERCP 塑料/金属支架，或 PTCD）／术前评估（增强 CT / MRI、肝功能与营养、麻醉评估）／活检（内镜活检或 EUS-FNA）。
- **手术（多数人走这一条）**：胰十二指肠切除（PD / Whipple）或保留幽门的胰十二指肠切除（PPPD）；切除范围含胰头、十二指肠、胆囊、胆总管下段、部分胃或幽门；重建包括胰肠、胆肠、胃空肠三处吻合；区域淋巴结清扫，切缘按病理记 R0 / R1 / R2。
- **术后与晚期**：辅助治疗（以氟尿嘧啶类或吉西他滨类为基础的方案在指南中被列出，方案与适应证由医生判断）／不可切除或转移后的系统治疗与临床试验／贯穿全程的胰酶替代、营养、血糖与症状管理。

### 发展趋势

只写已经发生的事，带日期或版本。

- **分期体系**：AJCC 第 8 版把壶腹单独设章，并按浸润深度把 T1 拆成 T1a / T1b 两个子级（2026-10-26 核对到「拆分」这一事实，原件未取得）。
- **术后并发症语言**：ISGPS 2007 统一胃排空延迟（DGE）定义、2016 修订术后胰瘘（CR-POPF）定义，使不同医院病历里的「胰瘘」可以互相对照。
- **分子检测**：MSI / dMMR 与 HER2 等标志物在壶腹癌中的检测比例近年上升，直接决定是否有免疫或靶向治疗的入口；不同医院开展程度差异较大。
- **试验组织方式**：壶腹癌专属注册试验数量很少，近年更多以「胆道恶性肿瘤」「罕见实体瘤」「MSI-H 实体瘤」等 basket 形式入组。
- **中文信息供给**：截至本项目编写时，未检索到面向患者的壶腹癌独立中文科普体系，内容仍主要附属于胰腺癌与胆管癌。

**来源**：AJCC 8th（未取得原件，据二次来源）｜ ISGPS DGE 2007 / CR-POPF 2016（未取得原件，据二次来源）｜ NCCN Ampullary Adenocarcinoma（版本未核实）

## 开发与本地验收

需要 Node.js 22+、Git、包管理器和可用 DSH Desktop；采用 SQLite 时另核验 node:sqlite 版本条件。宿主 peers 的范围仅是模板基线，请与目标 Desktop 实际依赖核对。

```bash
npm install
npm run check
npm run pack:check
npm pack
```

`npm run check` 只保证"能装"（语法 + 装包合同），第一天就该是绿的。`npm run audit` 管"还是不是家族里的一员"：版本三处一致、`lib/layout.js` 面板参数单一来源、检查链完整、文档与密钥卫生，**只看代码与文件，不看文档自述**。新项目刚生成时 audit 必然有 fail，那是待办清单；交付/发布前必须清零，存在 fail 不得发布（`npm run release:check` 一次跑完两者）。

跑的时间点：**每次改完**跑 `check`；**G2 原型确认后、写业务代码前**先跑一次 `audit`（这时缺的多是 `lib/layout.js`、`VERSION` 这类结构，越早补越便宜）；**交付/装机前**必须跑 `release:check`；**发布或投稿前**把 `npm run audit --json` 的 `xx/xx 通过 · N 失败 · M 待人工` 抄进 `docs/RELEASE.md` 的「家族一致性」一行。`✗` 是结构缺口（补齐，或在 `docs/DEV-REQUIREMENTS-<日期>.md` 写明偏离理由并由用户确认），`!` 是需人工判断的项（逐条给「已人工确认 / 确实没有」）。

`npm install` 可能按 npm 策略解析 peer；勿为消警告重复打包宿主 runtime。客户端本身是单文件；引入 TS/组件库后需添加构建步骤并保留单文件导出。

本地安装入口以当前 Desktop/CLI 帮助为准。安装后按 [docs/06-VALIDATION-AND-RELEASE.md](docs/06-VALIDATION-AND-RELEASE.md) 与官方自测完成真实 UI 验收，并填写 [docs/ACCEPTANCE.md](docs/ACCEPTANCE.md)。静态检查不代表已加载。

Logo 来源与使用限制见 assets/README.md。许可证、作者、仓库/发布策略由本项目维护者确认后填写；模板默认为 private/UNLICENSED。
